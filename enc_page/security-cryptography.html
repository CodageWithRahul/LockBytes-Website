Security & Cryptography

A clear guide to what LockBytes protects, how its layers fit together, and where their boundaries are. LockBytes is Windows file encryption software; it does not make every part of a device or workflow secure.

Get LockBytes →Explore the model

01 / PROTECTION MODEL

Several controls, each with a clear job.

LockBytes combines file encryption with a registered USB security layer. Optional Google Drive recovery is a separate path. Each control addresses a different part of the workflow.

Encrypted files

LockBytes uses AES-256-GCM for file encryption. Authenticated encryption is designed to detect changes to encrypted data.

Registered USB layer

A registered USB device adds a physical possession check to normal vault operations. It complements encryption and does not replace a strong unlock secret.

Optional recovery

Google Drive recovery is optional and depends on the account and configuration you choose. Review the recovery flow and privacy information before enabling it.

AES-256-GCM

AES-256-GCM provides authenticated encryption using a 256-bit key. In addition to protecting confidentiality, GCM provides authentication that allows modified ciphertext to be detected.

Fresh nonces

AES-GCM requires nonce uniqueness when used with the same key. LockBytes uses nonce construction appropriate to its chunked encryption workflow.

Argon2id

Passwords are not used directly as AES keys. Argon2id derives 256-bit key material using a salt and configurable computational and memory parameters.

03 / KEY HANDLING

Keys are the critical material.

Encryption protects data only while the relevant key material remains unavailable to an attacker. Protect your account, device, unlock credentials, and any recovery method.

Keep credentials private

Do not share passwords, recovery information, or authentication codes. Avoid storing them beside the files they protect.

Protect the running device

Malware or an attacker with access to an unlocked computer may capture plaintext or credentials while you work.

Make a recovery plan

Understand what you need to regain access before relying on an encrypted vault. Test recovery with noncritical data first.

04 / USB SECURITY LAYER

Physical possession adds a check.

LockBytes includes a registered USB security layer for normal vault operations. Keep the registered device under your control and maintain a safe plan if it is lost or damaged.

REGISTEREnroll device

Register the intended USB device through LockBytes.

CONNECTPresent device

Connect the registered device when the workflow requires it.

CHECKValidate access

The security layer checks for the registered device.

OPERATEUse the vault

Continue only through the application's permitted workflow.

CAREKeep it safe

Protect the USB device and use the documented recovery options.

A USB check is not a substitute for encryption, endpoint security, or a backup. Anyone who can use an already unlocked device may still access available plaintext.

05 / RECOVERY

Recovery changes the access story.

Optional Google Drive recovery can help restore access under the configured recovery process. It introduces an online account and service into the recovery path.

Opt in deliberately

Choose whether to configure recovery and understand what data is involved by reading the current privacy policy and in-app explanations.

Secure your Google account

Use a unique password and multifactor authentication where available. Account compromise can affect services tied to that account.

Check that recovery works

Keep recovery details current and confirm you can complete the process before depending on it for important files.

Cloud recovery is not the same as a local-first workflow. Availability and behavior can depend on Google services, connectivity, account access, and LockBytes configuration.

07 / THREAT MODEL

What the layers help address.

Security depends on the attacker's access and the state of your device. These examples are deliberately bounded.

Lost storage device

Encrypted files can help protect contents when a storage device is lost, provided the keys and credentials remain protected.

Unauthorized vault operation

The registered USB layer adds a possession check to the supported workflow. It does not defeat a compromised or unlocked computer.

Compromised endpoint

Malware, keyloggers, or privileged access can expose files while they are open. Encryption at rest cannot fully protect an infected active device.

08 / BOUNDARIES

Good security includes honest limits.

LockBytes focuses on protecting files through encryption and its supported access workflow. It is not a complete endpoint defense or a replacement for backups.

Situation What to understand
File is open Plaintext may be available to the operating system, applications, or an attacker controlling the device.
Weak or exposed credentials Anyone who obtains valid access information may undermine protections that depend on it.
Lost USB device Follow the documented recovery process; possession checks do not replace a recovery plan.
Device failure or deletion Encryption does not preserve data. Maintain separate backups and verify they can be restored.
Cloud account compromise Optional recovery can depend on account security and third-party service availability.

09 / PRACTICAL SECURITY

Small habits make the design work better.

Protect the whole workflow: the files, computer, credentials, USB device, and recovery path.

Get releases from the official page

Use the LockBytes download page and review release details. Verify checksums when they are provided.

Keep Windows protected

Install security updates, use reputable endpoint protection, and lock the screen when you step away.

Back up separately

Keep protected backups in a separate location and periodically test restoring them.

Use unique credentials

Use a password manager and do not reuse passwords across your Windows, Google, and other accounts.

Handle plaintext carefully

Close files when finished and consider temporary files, exports, and copies created by other applications.

Review recovery settings

Understand what is enabled and keep account recovery methods current and protected.

10 / SUMMARY

A layered tool with explicit boundaries.

LockBytes combines AES-256-GCM file encryption and a registered USB security layer for Windows workflows, with optional Google Drive recovery. The security outcome still depends on sound key handling, a protected device, and a recovery plan.
