THE SECURITY PROBLEM

A password is a gate.
LockBytes adds a key.

A protected file should not become readable simply because someone reaches your computer. LockBytes separates the protection model into layers: encrypted data, vault credentials, and the presence of a registered USB device.

It is a Windows desktop vault, not cloud storage. Your files stay local during normal encryption and decryption.

THE ENCRYPTION ENGINE

Strong encryption, explained plainly.

LockBytes uses AES-256-GCM authenticated encryption to protect encrypted file data and help detect unauthorized modification.

Large files are processed in chunks, so the application does not need to load an entire file into memory at once. Passwords, keys, and vault metadata remain part of the local protection model.

RECOVERY PROTECTION

Physical protection guards access.
Recovery protection guards against loss.

If your registered USB is lost, damaged, or unavailable, LockBytes can use your own Google Drive account as a recovery mechanism.

Google Drive is not needed for normal encryption or decryption. It is a separate, user-controlled recovery layer.

CAPABILITIES

Everything has a place in the model.

Practical controls for protecting files on a Windows computer.

01 / CORE

AES-256-GCM encryption

Authenticated encryption for protected file data, with modification detection.

02 / ACCESS

Registered USB vault

USB registration, identity, metadata, presence detection, and physical access control.

03 / PRIVACY

Local-first operation

Normal encryption and decryption happen on your device without a LockBytes file server.

04 / SCALE

Chunk-based processing

Large files can be handled without loading the entire file into memory at once.

05 / RECOVERY

Google Drive recovery

Your own account, the Drive API, and a dedicated LOCKBYTES_RECOVERY location for encrypted recovery data.

06 / CONTROL

Application and vault credentials

Separate credentials and local security material keep access under the user's control.
